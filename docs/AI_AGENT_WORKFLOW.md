# AI Agent Workflow

AI 에이전트를 함께 사용할 때의 작업 방식입니다.

## 왜 문서화하는가

AI 에이전트는 저장소의 규칙을 명확히 알려줄수록 안정적으로 작업합니다. 팀 컨벤션, 검증 명령, 금지할 결정, 개인정보 기준을 문서로 남겨두면 사람과 에이전트가 같은 기준으로 움직일 수 있습니다.

## 기본 운영 방식

- 큰 기능은 작은 작업으로 나눕니다.
- 작업 요청에는 목표, 범위, 완료 기준을 함께 적습니다.
- AI가 만든 변경도 사람이 리뷰합니다.
- 자동 생성된 설명을 그대로 믿지 말고 실제 diff와 검증 결과를 봅니다.

## 요청 템플릿

```text
목표:
범위:
수정해도 되는 위치:
수정하지 말아야 할 위치:
완료 기준:
검증 명령:
```

예시:

```text
목표: 아이 홈 화면 라우트를 추가한다.
범위: frontend/src/pages, frontend/src/routes
수정하지 말아야 할 위치: backend
완료 기준: /child에서 아이용 시작 화면이 보인다.
검증 명령: npm run format:check, npm run lint, npm run build
```

## AI에게 맡기기 좋은 일

- 라우트와 페이지 뼈대 생성
- 반복 UI 컴포넌트 분리
- README와 컨벤션 문서 업데이트
- 타입 정의 초안 작성
- 테스트 케이스 초안 작성
- 린트, 포맷, 빌드 오류 수정

## 사람이 먼저 결정해야 하는 일

- 서비스명, 캐릭터 이름과 말투
- 아이 개인정보 저장 정책
- 음성 원본 저장 여부
- 인증과 권한 모델
- 리포트 지표 정의
- AI/LLM 프롬프트 정책
- 배포 환경과 운영 비용

## 민감 정보 규칙

- 실제 아이 이름, 음성, 영상, 일기 원문을 샘플 데이터로 커밋하지 않습니다.
- 테스트 데이터는 가명과 짧은 더미 문장만 사용합니다.
- `.env`, 토큰, API 키는 커밋하지 않습니다.
- 영상과 음성 원본 저장은 별도 합의 전까지 구현하지 않습니다.

## 리뷰 체크리스트

- 요청 범위를 넘어서지 않았는가
- 사용하지 않는 패키지를 추가하지 않았는가
- 앱 실행, 린트, 빌드가 통과하는가
- 사용자 문구가 유아에게 안전하고 긍정적인가
- 부모 리포트 표현이 단정적 진단처럼 보이지 않는가
- 개인정보 저장과 노출 위험이 없는가
