# A501 DB 덤프 안내

제출용 익명화 덤프 `a501_latest_20260807_sanitized.sql.gz`가 이 폴더에 포함되어 있습니다. 운영 덤프에서 테이블 구조와 비민감 기준 데이터만 남겼으며, 보호자·아동·대화·일기·리포트·세션·토큰 등 사용자 데이터는 제외했습니다.

원본 운영 덤프에는 개인정보와 인증 데이터가 포함될 수 있으므로 제출하지 않습니다.

## 1. 포함 파일

```text
a501_latest_20260807_sanitized.sql.gz
```

## 2. 서버 내 제공 스크립트로 백업 생성

`deploy/scripts/backup-db.sh`가 운영 MySQL에서 압축 덤프를 생성합니다. 기본 저장 위치는 `/srv/a501-backups/mysql`이며 보존 기간 기본값은 14일입니다.

```bash
cd /srv/a501-deploy-state/runtime
ENV_FILE=/srv/a501-secrets/.env sh deploy/scripts/backup-db.sh
```

출력 예:

```text
/srv/a501-backups/mysql/a501-YYYYMMDDTHHMMSSZ.sql.gz
```

`export-db-backup.sh`는 DB 덤프를 생성하는 스크립트가 아닙니다. 이미 생성된 `.sql.gz` 파일을 EC2 루트 디스크 밖의 별도 마운트나 SCP 목적지로 복사할 때 사용합니다.

```bash
sh deploy/scripts/export-db-backup.sh \
  /srv/a501-backups/mysql/a501-YYYYMMDDTHHMMSSZ.sql.gz \
  user@backup-host:/backup/a501/
```

로컬 제출 폴더로 가져온 후 파일명을 `A501_DB_DUMP_YYYYMMDD.sql.gz` 형식으로 정리합니다.

## 3. 스크립트를 사용하지 못할 때 직접 mysqldump 실행

MySQL 컨테이너 이름이 `a501-mysql-1`인 기본 Compose 구성 예시입니다.

```bash
set -a
. /srv/a501-secrets/.env
set +a

docker exec a501-mysql-1 sh -c \
  'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" exec mysqldump \
   --single-transaction --routines --triggers \
   -u root "$MYSQL_DATABASE"' \
  | gzip -c > A501_DB_DUMP_YYYYMMDD.sql.gz
```

명령 출력이나 터미널 기록에 비밀번호가 노출되지 않도록 주의합니다.

## 4. 개인정보 처리

운영 DB에 실제 아동·보호자 정보가 존재한다면 원본 데이터를 그대로 제출하지 않습니다.

- 이메일, 이름, 생년월일, 프로필 이미지 키 등 개인정보를 익명화합니다.
- Refresh Token, 인증 토큰, 비밀키, 세션 데이터를 제거합니다.
- 아동 음성·대화 원문과 민감한 기록이 포함되는지 확인합니다.
- 평가에 필요한 시연용 계정과 최소 데이터만 남깁니다.
- 익명화 후 FK 관계와 시연 기능이 정상 동작하는지 확인합니다.

## 5. 덤프 검증

파일 존재 및 크기 확인:

```bash
ls -lh A501_DB_DUMP_YYYYMMDD.sql.gz
gzip -t A501_DB_DUMP_YYYYMMDD.sql.gz
```

Flyway 버전 확인:

```sql
SELECT version, description, success
FROM flyway_schema_history
ORDER BY installed_rank;
```

필요한 경우 복원 검증은 운영 DB가 아닌 별도 테스트 MySQL에서 수행합니다.

```bash
gunzip -c A501_DB_DUMP_YYYYMMDD.sql.gz | \
  mysql -h <TEST_DB_HOST> -u <USER> -p <DB_NAME>
```

검증 항목:

- 테이블 생성 성공
- FK 및 인덱스 생성 성공
- Flyway `V1`~`V14` 적용 이력 확인
- 기준 게임 데이터 조회
- 비밀값과 실제 개인정보가 포함되지 않았는지 최종 검색

- [x] 개인정보 및 사용자 활동 데이터 제거
- [x] 인증 토큰 및 비밀값 제거
- [x] Gzip 무결성 및 SQL 구조 검사 완료
- [x] 파일명을 날짜가 포함된 최종명으로 변경
- [x] `exec` 폴더에 압축 SQL 파일 추가

시연 계정과 기존 일기·리포트는 배포 서버 DB에만 유지됩니다. 제출 덤프를 로컬에 복원한 뒤 시연 데이터가 필요하면 별도의 가상 데이터로 생성합니다. 깨끗한 MySQL을 이용한 실제 복원 검증은 권장 확인 항목이며, 운영 DB에는 복원하지 않습니다.
