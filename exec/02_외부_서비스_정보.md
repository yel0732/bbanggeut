# A501 외부 서비스 정보

실제 Client Secret, API Key, 비밀번호, PEM 개인키는 이 문서에 작성하지 않습니다. 가입·발급 절차와 변수명만 기록합니다.

## 1. Google OAuth

용도: 보호자 소셜 로그인

필요 정보:

```text
GOOGLE_CLIENT_ID
VITE_GOOGLE_CLIENT_ID
```

설정 절차:

1. Google Cloud Console에서 프로젝트를 생성합니다.
2. OAuth 동의 화면을 설정합니다.
3. OAuth 2.0 Web Client를 생성합니다.
4. 승인된 JavaScript Origin과 Redirect URI를 등록합니다.
5. 동일한 Client ID를 Frontend 빌드와 Backend 검증 설정에 전달합니다.

등록값:

```text
개발 Origin: http://localhost:5173
운영 Origin: https://i15a501.p.ssafy.io
Redirect URI: 사용하지 않음
```

현재 Frontend는 Google Identity Services의 ID Token callback 방식을 사용합니다. Google Console에는 Redirect URI보다 승인된 JavaScript Origin을 정확히 등록해야 합니다.

Google Cloud Console에 등록된 Authorized JavaScript origins:

```text
https://i15a501.p.ssafy.io
```

## 2. AWS S3

용도: 보호자 및 아동 프로필 이미지 저장

필요 정보:

```text
STORAGE_PROVIDER
S3_UPLOAD_BUCKET
AWS_REGION
AWS_ACCESS_KEY_ID
AWS_SECRET_ACCESS_KEY
AWS_SESSION_TOKEN
```

권장 설정:

- 버킷은 public access를 차단합니다.
- 애플리케이션 전용 IAM 사용자 또는 EC2 IAM Role을 사용합니다.
- 해당 버킷과 지정 prefix에 필요한 최소 권한만 부여합니다.
- 장기 Access Key보다 EC2 IAM Role 사용을 우선합니다.
- 업로드는 Backend가 생성한 Presigned URL을 사용합니다.

## 3. GMS AI API

용도:

- 아이 답변에서 일기 정보 추출
- 다음 질문 생성 및 검증
- STT와 TTS
- 아이용 그림일기 생성
- 보호자용 일일 리포트 생성

필요 정보:

```text
GMS_KEY
GMS_BASE_URL
GMS_ANALYSIS_MODEL
GMS_RESPONSE_MODEL
GMS_REPORT_MODEL
GMS_CHILD_DIARY_MODEL
GMS_TIMEOUT_SECONDS
GMS_CHILD_DIARY_TIMEOUT_SECONDS
GMS_MAX_ATTEMPTS
STT_MODEL
TTS_MODEL
TTS_VOICE
```

GMS는 SSAFY에서 교육생 프로젝트용으로 제공하는 서비스이므로 별도 외부 회원가입은 필요하지 않습니다. SSAFY에서 안내한 방식으로 프로젝트용 API Key를 발급받아 AI Server의 `GMS_KEY` 환경 변수로 주입합니다. 실제 API Key 값은 제출 문서나 Git 저장소에 기록하지 않습니다.

API Key는 AI Server 런타임 환경에만 주입하며 Frontend에 전달하지 않습니다.

## 4. STUN/TURN 및 WebRTC

용도: 브라우저와 AI Server 사이의 WebRTC 연결

필요 정보:

```text
REALTIME_STUN_URLS
REALTIME_ICE_SERVERS
REALTIME_SIGNALING_URL
```

현재 AI Server는 Linux host network와 Google 공개 STUN 서버를 사용하며, 저장소와 Compose 설정에는 별도 TURN 서버가 구성되어 있지 않습니다.

```text
사용 STUN 서버: stun:stun.l.google.com:19302
사용 TURN 서버: 없음
WebSocket URL: wss://i15a501.p.ssafy.io/realtime/signaling
```

## 5. Let's Encrypt

용도: 운영 도메인의 HTTPS 인증서

필요 경로:

```text
CERTBOT_WEBROOT
LETSENCRYPT_LIVE_DIR
LETSENCRYPT_ARCHIVE_DIR
NGINX_CONFIG_FILE
```

최초 발급 전 Nginx는 `deploy/nginx-http.conf`로 실행하고, 인증서 발급 후 `deploy/nginx.conf`로 전환합니다. 운영 서버에서는 Certbot의 `certbot.timer`로 자동 갱신하며 `deploy/scripts/check-operations.sh`에서 타이머 활성화 상태와 인증서 만료일을 확인합니다.

## 6. GitLab 및 Jenkins

용도: 소스 관리와 자동 배포

필요 정보:

- GitLab 저장소 Credential
- GitLab webhook secret
- Jenkins 관리자 계정
- EC2 SSH Key 또는 서버 접근 정책
- Jenkins가 읽을 `/srv/a501-secrets/.env`

Jenkins는 `master` 브랜치 배포만 허용하며 webhook 경로는 다음 형태입니다.

```text
https://i15a501.p.ssafy.io/project/a501-deploy
```

비밀값은 Jenkins Credentials 또는 EC2 비밀 파일에만 저장합니다.
