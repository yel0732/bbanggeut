# A501 빵긋 포팅 매뉴얼

> 목적: GitLab에서 소스를 클론한 뒤 로컬 빌드, 테스트, Docker Compose 실행 및 Linux/EC2 운영 배포까지 재현하기 위한 문서입니다.  
> 보안: 실제 비밀번호, JWT Secret, GMS Key, AWS Secret, RSA Private Key는 Git에 기록하지 않습니다. 운영 값은 `/srv/a501-secrets/.env`에서 관리합니다.

## 1. 프로젝트 개요

A501 빵긋은 아동의 손 모션 게임과 AI 실시간 음성 대화를 바탕으로 아이의 일기와 보호자용 일일 리포트를 생성하는 서비스입니다.

```text
Browser
  └─ Nginx
      ├─ React 정적 파일
      ├─ /api/*       → Spring Boot Backend
      ├─ /realtime/*  → FastAPI AI Server(WebSocket signaling)
      └─ /grafana/*   → Grafana

Backend   → MySQL / Redis / AWS S3 / Google OAuth
AI Server → Redis / GMS / WebRTC(STT·TTS)
```

## 7. DB 접속 및 ERD 관련 정보

### 7.1 운영 DB 접속 구조

| 항목 | 값 |
|---|---|
| DBMS | MySQL 8.4 |
| Compose 호스트 | `mysql` |
| 포트 | `3306` |
| DB명 | `${MYSQL_DATABASE}`; 예시 `a501` |
| 애플리케이션 사용자 | `${MYSQL_USER}`; 예시 `a501_app` |
| JDBC URL | `jdbc:mysql://mysql:3306/${MYSQL_DATABASE}?useUnicode=true&characterEncoding=utf8&serverTimezone=UTC` |
| 외부 공개 | 공개하지 않음. Compose 내부 네트워크에서 Backend만 접속 |
| Backend 매핑 | `DB_URL`, `DB_USERNAME`, `DB_PASSWORD` |

`serverTimezone=UTC`는 JDBC 세션 기준 시간입니다. 부모 리포트 알림 시각은 DB의 `notification_minute`와 `time_zone`을 사용해 애플리케이션에서 변환합니다.

### 7.3 Flyway/ERD

운영 Backend 시작 시 다음 파일들이 버전 순으로 적용됩니다.

```text
backend/src/main/resources/db/migration/
V1__initial_schema.sql
...
V14__add_parent_role_and_admin_report_audit.sql
```

운영에서는 다음 쿼리로 적용 이력을 확인합니다.

```sql
SELECT installed_rank, version, description, installed_on, success
FROM flyway_schema_history
ORDER BY installed_rank;
```

## 13. 배포 특이사항

1. **WebRTC와 host network**  
   AI Server는 외부 브라우저의 UDP 미디어를 직접 받기 위해 `network_mode: host`를 사용합니다. Nginx는 WebSocket signaling만 프록시하며 WebRTC 음성은 프록시하지 않습니다.

2. **방화벽**  
   HTTP 80, HTTPS 443과 실제 ICE 후보에서 사용하는 UDP 통신이 AWS Security Group 및 UFW에서 허용되어야 합니다. 운영 환경에서 실제 후보 포트를 확인한 뒤 허용 범위를 확정합니다. NAT 환경에서 연결이 불안정하면 TURN 서버를 추가해야 합니다.

3. **TLS 인증서**  
   최초 인증서 발급 전에는 `deploy/nginx-http.conf`, 발급 후에는 `deploy/nginx.conf`를 사용합니다. Let's Encrypt live/archive 디렉터리는 Nginx 컨테이너에 읽기 전용으로 마운트합니다.

4. **PEM 환경변수**  
   실시간 티켓 Private/Public Key는 각각 PKCS#8/X.509 PEM 형식이어야 합니다. `.env`에서 여러 줄 PEM을 직접 저장할 경우 Compose 파싱이 깨질 수 있으므로 현재 애플리케이션이 지원하는 개행 표현을 사전 검증합니다. Private Key는 Git과 Jenkins 로그에 출력하지 않습니다.

5. **데이터 보존**  
   배포 전 MySQL 백업을 수행합니다. `docker compose down -v`, 광범위한 볼륨 삭제, `/srv` 재귀 삭제는 금지합니다.

6. **시간대**  
   JDBC 연결은 UTC이며, 사용자별 리포트 시각은 `notification_minute`와 IANA Time Zone(예: `Asia/Seoul`)으로 계산합니다. DB에 표시된 시각과 API 응답 시각을 혼동하지 않습니다.

7. **GMS 모델 변경**  
   `/srv/a501-secrets/.env` 수정 후 AI Server를 재생성하고 다음 명령으로 실제 컨테이너 값을 확인합니다.

```bash
docker exec a501-ai-server-1 sh -c 'env | grep "^GMS_.*_MODEL="'
```

8. **Health Check 의존성**  
   AI `/health/ready`와 Backend readiness는 Redis·DB 같은 의존 서비스 상태에 따라 503을 반환할 수 있습니다. CI 단위 테스트에서는 외부 Redis가 필요 없는 테스트와 통합 테스트를 분리해야 합니다.

## 14. Jenkins CI/CD

`master` 브랜치에서 다음 순서로 실행됩니다.

```text
Checkout
→ master 확인
→ Backend 테스트
→ AI Server 테스트
→ AI/Backend/Nginx 이미지 빌드
→ MySQL 백업
→ Redis 배포
→ AI Server 배포 및 Health Check
→ Backend 배포 및 Health Check
→ Nginx 배포 및 Health Check
→ Smoke Test
→ 실패 시 이전 이미지 Rollback
```

Jenkins UI는 외부에 직접 노출하지 않고 SSH 터널을 사용합니다.

```powershell
ssh -i <PEM 파일> -L 8080:127.0.0.1:8080 ubuntu@i15a501.p.ssafy.io
```

접속: `http://127.0.0.1:8080`

Jenkins Credentials Store에는 GitLab 접근 및 배포에 필요한 자격증명을 등록합니다. 실제 Credential ID와 GitLab Webhook URL은 보안상 Git에 기록하지 않고 운영 인수인계 문서에 별도 보관합니다.
